Cadence

A calendar you talk to. Type “move both standups to 10am” and an LLM agent finds, edits and adds the events, holding anything that conflicts until you confirm it.

How it works

  • Quick mode. One LLM call turns a sentence into a validated add, update or remove, checked against Pydantic models with Instructor. Works with Claude or a local Ollama model.
  • Agent mode. A hand-written tool-calling loop on the Anthropic SDK (search, add, update, remove) with an 8-step cap. Validation errors go back to the model so it can correct itself.
  • Safe by construction. The agent has no confirm tool, so it can't approve its own conflicts, and the session id never appears in a tool schema, so it can't reach another visitor's calendar.

Problems I solved

  • The model was bad at date math, so now it doesn't do any. The prompt carries a 7-day lookup table, and the date logic became plain, testable Python.
  • Local inference was too slow. I moved from Ollama to Claude Haiku behind a provider factory, which made quick mode feel instant and the agent loop practical.
  • An eval failed, and the test was wrong. The agent asked which of two events I meant. I fixed the test instead of the prompt, so it still asks when a request is ambiguous.

Delphi

AI writes code for you; Delphi makes sure you understand it. An AI senior reviewer reads your real GitHub pull requests and won't approve one until you can explain what your code does.

How it works

  • Idea to tickets. Describe a project in plain words and Claude turns it into 3–5 tickets that say why and what “done” means, never how.
  • Instant, Socratic review. The moment you open a pull request or push to it, a GitHub App webhook fires and Delphi starts reading the diff, with a review on the PR about 30 seconds later: questions, a security or correctness finding, and a hint ladder (the concept, then where to look, then a small snippet). It never posts the fix.
  • Comprehension gate. Delphi asks 2–3 questions about your own diff. A weak answer gets the next hint, not approval. Pass, and the bot approves the PR.

What I built

  • Built with a teammate in 26 hours at Hack the Change 2026: a GitHub App that reviews learners’ real pull requests and won’t approve one until they can explain their own code.
  • Designed the Claude reviewer with Pydantic-validated structured output: a Socratic review flagging security and correctness bugs (e.g. CWE-94 code injection), hints that never give the fix, and graded questions on the diff.
  • Built the FastAPI webhook pipeline: HMAC-SHA256 signature checks, an immediate response with the review run in the background, duplicate-delivery handling, and PR approval on a passing score; covered by a 99-test pytest suite.
